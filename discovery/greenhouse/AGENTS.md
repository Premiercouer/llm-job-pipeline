# Greenhouse Job Pipeline

## Purpose

This project scans Greenhouse boards, discovers new relevant jobs, and outputs a standard jobs JSON that the downstream Job Match can read directly.

Main scripts:

```text
scripts/01_search_jobs.py
scripts/02_fetch_jd.py
```

Title screening rules:

```text
instructions/title_screening.md
```

---

## Pipeline

Full sequence:

```text
01_search_jobs.py
→ scan Greenhouse boards
→ seen dedupe by stable job ID
→ stage unseen IDs in this run's prepare artifact
→ location filter
→ updated_at last-7-days filter
→ title-screen worker (../title_screen.py) runs the broad title screen (semantic match)
→ Python validates/finalizes and commits seen state in one go
→ output candidates that passed title screening

02_fetch_jd.py
→ read Stage 01 candidates
→ fetch Greenhouse detail / JD
→ final 7-day check using first_published
→ clean JD
→ output final jobs JSON
```

Stage 01 must complete successfully before Stage 02 runs.

---

## Pre-run Checks

By default, Stage 01 reads:

```text
outputs/greenhouse_boards_relevant_merged.json
```

Confirm this registry file exists before running Stage 01.

---

## Stage 01

Prepare:

```bash
python scripts/01_search_jobs.py
```

The title-screen worker reads `instructions/title_screening.md` and the
`.runtime/01_title_screen_input.json` generated by prepare, screens the titles in chunks with
single-turn model calls, and writes the complete partition result to
`.runtime/01_title_screen_results.json` (only if every title is covered):

```bash
python ../title_screen.py --source greenhouse
```

An interactive agent session can still produce the same results file by hand instead. Then run:

```bash
python scripts/01_search_jobs.py --phase finalize
```

Production seen state:

```text
.runtime/greenhouse_seen_jobs.json
```

Stable ID:

```text
greenhouse:{board_token}:{job_id}
```

Unseen IDs discovered in this run are staged in memory and in the prepare artifact; only after the Title Screen
results pass the completeness check and the candidate output passes validation are they committed to seen state in a single atomic commit.

Default parallelism:

```text
Board workers: --workers 20
Title screen: chunks of 150 titles per model call (--chunk-size), sequential
```

The title-screen worker embeds the following rule file in its system prompt:

```text
instructions/title_screening.md
```

Each object in the batch input has only:

```json
{
  "source_key": "...",
  "position": "..."
}
```

When Stage 01 completes, it generates the candidate output and a handoff.

---

## Stage 02

After Stage 01 succeeds, run:

```bash
python scripts/02_fetch_jd.py
```

Stage 02 reads its input automatically from the Stage 01 handoff.

Main flow:

```text
title-pass candidates
→ Greenhouse detail API
→ JD
→ first_published <= 7 days
→ final output
```

Default:

```text
--workers 3
```

---

## Date Rules

```text
updated_at
→ Stage 01 cheap 7-day filter

first_published
→ Stage 02 final 7-day filter
```

Whether a job is ultimately output is determined by `first_published`.

---

## Final Output

Final format:

```json
{
  "date": "YYYY-MM-DD",
  "job_count": 1,
  "jobs": [
    {
      "company": "...",
      "position": "...",
      "jd": "...",
      "apply_url": "...",
      "source_key": "..."
    }
  ]
}
```

Output directory:

```text
outputs/
```

## Testing

After changing code, run these first:

```text
syntax check
→ unit tests
→ small-scale Stage 01 test
→ Stage 02 test
→ inspect final output
```

Small-scale Stage 01 test example:

```bash
python scripts/01_search_jobs.py --limit-boards 2
# current session writes .runtime/01_title_screen_results_test.json
python scripts/01_search_jobs.py --phase finalize --limit-boards 2
```

Tests use a separate seen state:

```text
.runtime/greenhouse_seen_jobs_test.json
```

Do not automatically continue to a full production run after testing.

---

## Repeated Testing

A test run writes to:

```text
.runtime/greenhouse_seen_jobs_test.json
```

If the same set of boards is reused, previously seen jobs are skipped as seen.

To retest the full pipeline from scratch, specify a new test seen state, for example:

```bash
python scripts/01_search_jobs.py \
  --limit-boards 5 \
  --test-seen-state .runtime/greenhouse_seen_jobs_test_fresh.json
```

---

## Production Run

Normal production sequence:

```bash
python scripts/01_search_jobs.py
python ../title_screen.py --source greenhouse
python scripts/01_search_jobs.py --phase finalize
python scripts/02_fetch_jd.py
```

When done, check the latest final jobs JSON generated in `outputs/`.
